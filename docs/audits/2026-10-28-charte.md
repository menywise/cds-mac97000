# Audit de la charte graphique, 28/10/2026

Audit du socle (lancé en local) et d'une installation construite sur le socle (site publié). Il
mesure ce qui s'affiche à l'écran, pas ce que dit le code, et il éprouve les garde-fous en y plantant
des fautes. Les exemples restent anonymes, comme dans `docs/REMONTEES.md` : « l'installation »
désigne le projet audité.

## Méthode

| Besoin                  | Outil                                                                                               |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| Contraste réel du texte | axe-core 4.13 (règle `color-contrast`), cas « non tranchés » compris : texte sur dégradé, sur image |
| Contraste au survol     | survol forcé élément par élément (Playwright), puis axe-core sur l'élément seul                     |
| Focus clavier           | capture avec focus contre capture sans focus, contraste maximal des pixels changés, seuil 3:1       |
| Paires de jetons        | calcul de `scripts/verifier-contrastes.mjs`, avec les paires qu'il ne contrôlait pas                |
| CSS livré               | `@projectwallace/css-analyzer` sur la construction                                                  |
| Solidité des garde-fous | test par mutation : `scripts/mutations-charte.sh`                                                   |

Contre-épreuve : chaque mesure a d'abord été lancée sur une page en défaut connu, pour vérifier
qu'elle échoue bien (47 échecs attendus et trouvés avec les couleurs d'origine). Le focus mesuré à
l'aide du style calculé donnait de faux positifs (ombres transparentes de Tailwind) : seule la
comparaison de pixels a été retenue.

## Constats

| #   | Écart                                                                                                                | Mesure                | WCAG   | Priorité |
| --- | -------------------------------------------------------------------------------------------------------------------- | --------------------- | ------ | -------- |
| 1   | Couleurs de données (table de familles dans le code, catégories saisies en base) posées en texte sans correction     | 1,86 à 4,48:1         | 1.4.3  | P1       |
| 2   | Catégories en base pas encore affichées, donc invisibles du robot de recette                                         | jusqu'à 2,15:1        | 1.4.3  | P1       |
| 3   | Installation : l'ombre de `module-card` efface l'anneau de focus des liens (couche utilitaire contre couche de base) | aucun pixel ne change | 2.4.7  | P1       |
| 4   | Socle : anneau de focus à 30 % d'opacité (`ring-ring/30`) sur boutons, onglets, bouton du mot de passe               | 1,7:1                 | 2.4.7  | P1       |
| 5   | Bordure des champs (`--input` sur `--card`)                                                                          | 1,53:1                | 1.4.11 | P2       |
| 6   | Garde-fous : 6 fautes sur 14 acceptées par le hook ; `border-l-amber-500` en production                              | voir ci-dessous       | —      | P2       |
| 7   | Bandeau cookies du socle qui recouvre l'élément qui a le focus                                                       | élément caché         | 2.4.11 | P2       |
| 8   | Texte sur dégradé (bandeau de module) : axe ne tranche pas                                                           | 4,70:1 au calcul      | 1.4.3  | P3       |

Un contrôle à l'écran ne protège pas une couleur stockée en base : le constat 2 n'apparaît dans
aucune recette tant qu'aucune donnée n'utilise la catégorie fautive. D'où la règle : une couleur
de données passe par `couleurLisible()` (`src/lib/couleurs.ts`).

Le robot de recette ne voyait pas non plus : le survol, le focus, les 361 cas qu'axe ne tranche
pas (texte sur dégradé, caractères spéciaux) et le contraste des éléments non textuels.

## Test par mutation des garde-fous

Une faute à la fois, dans une copie jetable du dépôt, jugée par le vrai `.githooks/pre-commit`.

| Faute plantée                             | Avant (socle) | Après (socle) |
| ----------------------------------------- | ------------- | ------------- |
| Variante sombre `dark:`                   | refusée       | refusée       |
| `text-orange-600`                         | refusée       | refusée       |
| Préfixe composé `border-l-amber-500`      | non testée    | refusée       |
| `text-[#ea580c]`                          | **passe**     | refusée       |
| `style={{ color: "#ea580c" }}`            | **passe**     | refusée       |
| Table hexadécimale dans un `.ts`          | **passe**     | refusée       |
| `fill="#f59e0b"` sur un SVG               | refusée       | refusée       |
| `style={{ color: "rgb(…)" }}`             | **passe**     | refusée       |
| Gris sur un intitulé                      | refusée       | refusée       |
| 6 textes gris dans un nouveau fichier     | refusée       | refusée       |
| `opacity-60`                              | refusée       | refusée       |
| `text-foreground/50`                      | **passe**     | refusée       |
| Couleur venue de la base posée en texte   | **passe**     | refusée       |
| `:root` de `styles.css` modifié à la main | refusée       | refusée       |
| Jeton à 2,1:1, puis `npm run jetons`      | refusée       | refusée       |

Dans l'installation, la copie du socle modifiée est aussi refusée (contrôle de `socle.json`).
Relancer : `bash scripts/mutations-charte.sh` ; il sort en échec si une faute passe.

## Suites données

| Constat    | Correction                                                                                                                                                                        | Demande de fusion (socle) |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 1, 2, 3, 4 | `couleurLisible()` ; anneau de focus plein décalé de 2 px ; contour au focus de `module-card` côté installation                                                                   | #44                       |
| 6          | Lint et `verifier-couleurs.mjs` : préfixes composés, valeurs arbitraires ; cliquet : couleurs en dur, styles en ligne, opacité par modificateur ; `tests/unit/garde-fous.test.ts` | #45                       |
| 5, 7       | Contour des champs à 3:1 ; focus jamais caché sous un bandeau                                                                                                                     | #46                       |

Mesure dans l'installation, après publication des corrections 1 à 4 : 0 échec de contraste au
repos (48 avant) et 0 focus invisible (13 avant) sur les pages remesurées.

Restent à traiter dans l'installation : un bouton de validation à 4,48:1 au survol, le focus du
champ de recherche du glossaire (1,02:1), et la paire du bandeau de module à ajouter à
`verifier-contrastes.mjs`.

## Ce que l'audit n'a pas couvert

- Les rôles membre et rédacteur, le mobile et le compte de démonstration de l'installation.
- Les pages connectées du socle (aucun compte de recette pour le socle).
- La lisibilité en conditions réelles : une personne du terrain, sur un poste du bloc, qui fait
  trois tâches chronométrées (lire une famille de fil, ouvrir une fiche au clavier seul, dire la
  catégorie d'une transmission). C'est la seule preuve qui ne vient pas du code.
